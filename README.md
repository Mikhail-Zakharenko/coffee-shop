# Aroma Coffee — сайт кофейни

## 1. Описание проекта

Aroma Coffee — адаптивный сайт кофейни, созданный с использованием HTML5 и SCSS.

Цель проекта — отработать навыки семантической HTML-разметки, адаптивной вёрстки, применения Flexbox и CSS Grid, а также организации SCSS-кода по отдельным файлам.

Дизайн выполнен в тёплой цветовой гамме с акцентом на фотографии кофе, типографику и уютную атмосферу.

## 2. Технологии

- HTML5 — семантическая разметка страницы.
- SCSS — стилизация и организация CSS-кода.
- CSS3 — Flexbox, Grid, медиазапросы, переходы и адаптивная вёрстка.
- Google Fonts — шрифты DM Sans и Playfair Display.
- SVG — иконка сайта (favicon).
- Live Sass Compiler — компиляция SCSS в CSS.
- Live Server — локальный запуск сайта в браузере.

JavaScript в проекте не используется.

| Файл              | Назначение                                       |

| `_variables.scss` | Цвета, шрифты, размеры и другие общие значения   |
| `_base.scss`      | Базовые стили, контейнер, заголовки и кнопки     |
| `_header.scss`    | Шапка и навигация                                |
| `_hero.scss`      | Главный экран                                    |
| `_menu.scss`      | Карточки напитков                                |
| `_about.scss`     | Информация о кофейне                             |
| `_footer.scss`    | Призыв к действию и подвал                       |
| `style.scss`      | Главный файл, подключающий остальные SCSS-модули |
| `style.css`       | Скомпилированные стили, используемые браузером   |

## 4. Как запустить проект

1. Открой папку проекта в Visual Studio Code.
2. Убедись, что установлено расширение Live Sass Compiler.
3. Открой `src/scss/style.scss`.
4. Запусти команду **Watch Sass**.
5. Убедись, что создан или обновлён файл `src/css/style.min.css`.
6. Открой `index.html` через расширение Live Server.

Браузер загружает `src/css/style.min.css`. Исходные SCSS-файлы подключаются друг к другу через `@use` и непосредственно браузером не обрабатываются.

Для работы с внешними фотографиями и Google Fonts требуется подключение к интернету.

## 5. Техническое задание для AI

### 5.1. Цель

Создать современный адаптивный сайт кофейни Aroma Coffee на основе HTML5 и SCSS.

Код должен быть понятным, структурированным, поддерживаемым и пригодным для дальнейшего обучения и расширения проекта.

### 5.2. Общие требования

- Использовать HTML5 и семантические элементы.
- Для стилизации использовать SCSS.
- Не использовать JavaScript и сторонние CSS-фреймворки без отдельного требования.
- Применять современные возможности CSS.
- Использовать Flexbox и CSS Grid в соответствии с задачей каждого блока.
- Обеспечить адаптивность для настольных компьютеров, планшетов и смартфонов.
- Использовать понятные имена классов в стиле BEM.
- Не допускать горизонтальной прокрутки страницы на типичных размерах экранов.
- Обеспечить корректное отображение изображений, текста, ссылок и кнопок.
- Не добавлять не предусмотренные заданием элементы и функции.

### 5.3. Структура страницы

Сайт должен содержать следующие блоки.

#### 1. Шапка — Header

- Логотип Aroma.
- Навигация: «Главная», «Меню», «О нас», «Контакты».
- Кнопка перехода к меню.
- Закрепление шапки в верхней части окна при прокрутке.
- Адаптивное расположение элементов на мобильных устройствах.

#### 2. Главный экран — Hero

- Небольшой вводный текст.
- Крупный заголовок с акцентом на ключевых словах.
- Краткое описание кофейни.
- Кнопка перехода к меню.
- Ссылка на блок «О нас».
- Декоративный информационный элемент.
- Крупная фотография кофе.
- Две колонки на широких экранах и одна колонка на мобильных.

#### 3. Меню напитков — Menu

- Заголовок и краткое описание.
- Три карточки напитков: капучино, эспрессо и латте.
- В каждой карточке должны быть фотография, название, цена и описание.
- Для отдельных карточек допускаются информационные метки.
- Сетка из трёх колонок на широком экране, двух на планшете и одной на узком экране.
- Кнопка перехода к контактному блоку.

#### 4. Блок «О нас» — About

- Фотография интерьера кофейни.
- Заголовок и описание.
- Ссылка на контактный блок.
- Три информационных показателя.
- Две колонки на широком экране и одна на мобильном.

#### 5. Призыв к действию — Visit

- Контрастный фон.
- Заголовок с приглашением посетить кофейню.
- Краткий текст.
- Кнопка связи.

#### 6. Подвал — Footer

- Логотип.
- Краткий слоган.
- Информация об авторских правах.

### 5.4. Требования к дизайну

Использовать тёплую цветовую гамму:

- Основной цвет: `#8b5638`.
- Тёмный цвет текста: `#30241e`.
- Основной фон: `#fcf8f3`.
- Светлый акцентный фон: `#f4ece3`.
- Цвет дополнительного текста: `#81736b`.

Шрифты:

- DM Sans — основной текст.
- Playfair Display — заголовки и логотип.

Дополнительные требования:

- Крупная выразительная типографика.
- Достаточные отступы между блоками.
- Скруглённые углы карточек и изображений.
- Ненавязчивые тени.
- Плавные переходы при наведении.
- Сохранение визуальной иерархии на разных размерах экрана.

### 5.5. Требования к SCSS-архитектуре

Разделить стили по отдельным файлам:

- `_variables.scss` — переменные проекта.
- `_base.scss` — базовые стили и общие компоненты.
- `_header.scss` — шапка.
- `_hero.scss` — главный экран.
- `_menu.scss` — карточки меню.
- `_about.scss` — блок «О нас».
- `_footer.scss` — призыв к действию и подвал.
- `style.scss` — единая точка входа для подключения модулей.

Правила организации:

1. Использовать `@use`, не применять устаревший `@import`.
2. Подключать необходимые модули в `style.scss`.
3. Использовать переменные для повторяющихся цветов, шрифтов, размеров и других значений.
4. Подключать общий модуль переменных в тех SCSS-файлах, где он необходим.
5. Не дублировать общие стили без необходимости.
6. Не допускать чрезмерной вложенности селекторов.
7. Размещать медиазапросы рядом с соответствующими стилями или организовывать их последовательно и единообразно.
8. Компилировать `style.scss` в `src/css/style.min.css`.
9. Не редактировать скомпилированный CSS вручную, если он генерируется компилятором.

### 5.6. Требования к адаптивности

Предусмотреть адаптивное поведение как минимум для следующих диапазонов:

- Широкие экраны: более 1200 px.
- Планшеты и небольшие ноутбуки: 681–1200 px.
- Смартфоны: до 680 px.

Это ориентировочные диапазоны, а не обязательные единственные контрольные точки. При необходимости разрешается добавлять дополнительные медиазапросы.

Проверить:

- изменение количества колонок;
- перестроение двухколоночных блоков;
- размеры и пропорции изображений;
- перенос текста и кнопок;
- навигацию;
- внутренние и внешние отступы;
- отсутствие горизонтальной прокрутки.

### 5.7. Доступность и семантика

- Указывать `lang="uk"` и метатег `viewport`.
- Использовать семантические элементы HTML.
- Добавлять содержательные `alt` к значимым изображениям.
- Использовать пустой `alt` для исключительно декоративных изображений.
- Обеспечивать видимый фокус клавиатуры.
- Проверять контраст текста и фона.
- Использовать ссылки для переходов и кнопки для действий.
- Проверять корректность адресов ссылок и якорей.

### 5.8. Проверка результата

После реализации AI должен:

1. Проверить корректность HTML-разметки.
2. Убедиться, что SCSS компилируется без ошибок.
3. Проверить, что `style.css` подключён правильно.
4. Проверить работу всех ссылок навигации.
5. Проверить адаптивность на нескольких ширинах экрана.
6. Проверить загрузку изображений, шрифтов и favicon.
7. Исправить выявленные ошибки.
8. Кратко объяснить структуру проекта и назначение файлов.

### 5.9. Ограничения

- Не создавать отдельный CSS-файл для каждого блока.
- Не подключать SCSS напрямую в HTML.
- Не использовать CSS-фреймворки без согласования.
- Не добавлять JavaScript, если он не требуется заданием.
- Не усложнять архитектуру проекта избыточными абстракциями.
- Не заявлять о проверке в браузере, если фактическая проверка не проводилась.
